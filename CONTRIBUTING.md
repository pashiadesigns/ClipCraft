# Contributing

Use issues for bugs and scoped proposals. Include the version and a synthetic
reproduction; remove identifying information from screenshots.

Keep the document engine independent from UI code. Use the shared engine in the
desktop and CLI, preserve saved-project compatibility and one-step Undo, and add
meaningful persistence/rendering tests. Run [the checks](docs/building.md).
Native verification should use synthetic content.

Do not commit credentials, personal captures, build output, or proprietary assets.
Preserve third-party notices when adapting licensed code. Contributions use the
repository license unless explicitly stated otherwise. Use SECURITY.md to report
security vulnerabilities.
